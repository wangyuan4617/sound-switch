========================================================
 sound-switch 使用说明
 按 HyperX 耳机开关机自动切换系统默认输出设备
========================================================

【这个程序做什么】
监听耳机 USB 接收器上报的数据：
  · 耳机开机  → 把 Windows 默认输出设备自动切到耳机
  · 耳机关机  → 自动恢复成“切换前那台设备”
所有配置、状态、日志都保存在本文件夹内，不写系统目录、无需安装程序。
（后台常驻时无窗口，空闲占用约 0.16% 单核、内存 6～7MB）


========================================================
 一、安装（双击即可，不需要输入命令）
========================================================
1. 把整个文件夹放到合适位置，例如：D:\GreenTools\sound-switch
   （建议用英文路径；文件夹可以随意移动，程序不依赖固定路径）

2. 双击运行：安装登录自启.bat
   脚本会自动完成：
     · 注册“登录时自动启动”计划任务（以当前用户身份、普通权限、无窗口）
     · 立即在后台启动一次（不用重新登录就能生效）
   结束时窗口会提示“按回车键关闭窗口”，不会一闪而过。

3. 双击运行：查看运行状态.bat  → 确认安装结果
   正常应看到：
     【登录自启】已安装
     【后台进程】正在运行 ... 窗口: 无窗口（正常）
     【当前默认输出设备】...（能看到耳机端点）

4. 开关一次耳机电源，然后再次运行“查看运行状态.bat”或看日志：
   · 开机 → 日志出现「收到设备开机事件」+「已把角色 console 的默认输出切换为 …耳机…」
   · 关机 → 日志出现「收到设备关机事件」+「已把角色 console 的默认输出切换为 …原设备…」


========================================================
 二、卸载
========================================================
双击运行：卸载登录自启.bat
  · 删除计划任务
  · 结束后台实例
之后可以直接把整个文件夹删掉（系统里不留任何东西）。


========================================================
 三、文件说明
========================================================
sound-switch.exe            主程序（手动运行会显示黑窗口，可看到日志）
sound-switch-launch.exe     无窗口启动器（登录自启用的是它）
config.json                 配置（见第五节；删掉会自动生成默认配置）
使用说明.txt                本文件
安装登录自启.bat            ← 双击安装
卸载登录自启.bat            ← 双击卸载
查看运行状态.bat            ← 双击查看状态与日志
scripts\                    命令行用的 PowerShell 脚本（进阶用法）


========================================================
 四、常用操作（可选，命令行）
========================================================
查看状态      ：双击 查看运行状态.bat
临时停止      ：Get-Process sound-switch | Stop-Process
重新启动      ：Start-ScheduledTask -TaskName sound-switch
手动切到耳机  ：.\sound-switch.exe set-default
恢复原默认    ：.\sound-switch.exe restore
列出设备      ：.\sound-switch.exe list
修改配置后生效：先 Get-Process sound-switch | Stop-Process，再 Start-ScheduledTask -TaskName sound-switch
日志文件      ：logs\sound_switch.log（超过 512KB 自动轮转为 .log.1）


========================================================
 五、配置说明（config.json，改完需重启后台实例）
========================================================
vendor_id / product_id   耳机 HID 的 VID / PID，本耳机为 1008 / 2702
audio_keyword            用于在系统输出设备里认出耳机的“名称关键词”
                         （默认 HyperX Cloud Stinger Core Wireless，不区分大小写）
roles                    需要切换的角色，可多选：
                         console（常规程序）/ multimedia（多媒体）/ communications（通信）
rescan_interval_ms       重新枚举 HID 的间隔，默认 2000；调大更省 CPU，调小发现更快
read_timeout_ms          HID 读取超时，默认 500，一般不用改
endpoint_wait_ms         收到开机事件后，等待耳机音频端点出现的最长时间（默认 15000）
dry_run                  演练模式：true 时只打印将要执行的动作，不真正切换
log_level                日志级别：info（默认，只打印开关机等关键事件）
                         / debug（额外打印音量、原始 HID 数据，用于排查）
log_max_kb               单个日志文件大小上限（默认 512KB）


========================================================
 六、换电脑 / 重装系统
========================================================
把整个文件夹拷到新电脑 → 双击「安装登录自启.bat」即可。
注意两点：
1) 不要拷贝 state.json（新电脑的音频设备编号不同，程序会自动重新识别耳机）
2) DTS 空间音效要在新电脑上重设一次（该设置保存在系统里，不跟着程序走）：
   设置 → 系统 → 声音 → 选择耳机 → 空间音效 → DTS Headphone:X
   设置一次即可长期有效，不会因为耳机开关机而重置。


========================================================
 七、常见问题
========================================================
Q: 双击 .bat 后提示“无法加载文件…因为在此系统上禁止运行脚本”
A: 本脚本已用 -ExecutionPolicy Bypass 方式调用 PowerShell，正常不会出现。
   若仍出现，请用“以管理员身份运行”的 PowerShell 执行一次：
     Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Q: 提示找不到文件 / 不是内部或外部命令
A: 请保持包的目录结构：两个 exe、config.json、三个 .bat 在同一层，
   scripts 文件夹也在同一层。

Q: 双击 exe 时 Windows 提示“已保护你的电脑”（SmartScreen）
A: 点「更多信息」→「仍要运行」。exe 没有数字签名，属于正常提示。

Q: 为什么后台看不到窗口？
A: 这是设计如此：登录自启用的是无窗口启动器，避免每次开机弹一个黑窗口。
   需要看运行情况时，用「查看运行状态.bat」或看 logs\sound_switch.log。

Q: 会不会影响电脑性能？
A: 空闲时约占 0.16% 单核（12 核机器上约 0.013%）、内存 6～7MB。
   HID 读取是阻塞等待，不空转；日志只在有事件时写。

Q: 耳机开机后默认设备没切换？
A: 依次检查：
   1) 「查看运行状态.bat」里后台进程是否在运行
   2) logs\sound_switch.log 里有没有「收到设备开机事件」
   3) config.json 的 audio_keyword 是否匹配你系统里耳机的显示名称
      （用 .\sound-switch.exe list 可以看到实际名称）
   4) 临时把 log_level 改成 debug 看详细过程
